What PR 6089 changes: one list of names instead of two

An explainer for gnolang/gno pull request 6089. Generated by claude-opus-5. No review findings on this page.

Gno rejects f = nil when f is a function you declared with func f() {}. Something has to remember, for every name in the program, whether that name is a function declaration. Two pieces of memory held that same fact. This change keeps one and deletes the other.

Where names live

The gno compiler builds one StaticBlock per scope: one for the package, one per file, one per function body, one per if, one per loop. Each block keeps the names declared directly inside it, in a plain list, plus several side lists indexed the same way.

  StaticBlock for package main

  Names        [ "f",          "g",           "main"       ]
  Types        [ func(),       func(),        func()       ]
  NameSources  [ NSFuncDecl,   NSValueDecl,   NSFuncDecl   ]   how each name got here
                     0              1              2

NameSources answers "what kind of declaration introduced this name". NSFuncDecl means a top-level func; NSValueDecl means a var or const; there are eleven kinds in all, covering parameters, results, range variables, imports and the rest.

The second list

Alongside it sat UnassignableNames, a flat list of names you may not assign to. Only one line in the whole compiler ever appended to it, and that line sat immediately below the line that recorded the very same fact in NameSources.

  gnovm/pkg/gnolang/preprocess.go, before this change

  pkg.Reserve(false, nx, n, NSFuncDecl, -1)              records it once
  pkg.UnassignableNames = append(pkg.UnassignableNames, n.Name)  records it twice

So the name promised more than it held. It was never "all the names you cannot assign to". It was "the top-level functions", written a second time.

What the other unassignable names do instead

Constants, type names and built-ins are all refused too, and none of them ever went through that list. Each is caught earlier, by a different check, with its own error message.

You writeMessageWhich check
f = nil, f a declared funcnot assignablethe one this pull request rewrites
println = nilcannot assign to uverse printlnassertValidAssignLhs, on the built-in scope
c = 2, c a constantcannot assign to const cassertValidAssignLhs, on the const list
T = 1, T a type namecannot assign to const Tsame, type names are constants here

All three of those run before the func-declaration check, inside AssignStmt.AssertCompatible. That ordering is what makes the func case the only one left for the rewritten code to answer.

The check, before and after

The shape does not change: start at the block holding the assignment, walk out to enclosing blocks until the name is found, then answer. Only the answering step changes.

  walking outward from the assignment

     func main() { f = nil }        the name is not declared here
              │
              ▼
     file block                       nor here
              │
              ▼
     package block   Names[0] == "f"  found, index 0
              │
              ▼
     before  is "f" somewhere in UnassignableNames?   scan the whole list
     after   is NameSources[0].Type == NSFuncDecl?     one array read

The two answers agree because the same line wrote both, at the same index, at the same moment.

The wire format

StaticBlock has an amino schema, and amino numbers fields by position. Deleting a field would shift every field after it and silently reinterpret old bytes. The repository already has a mechanism for that: leave a blank placeholder where the field was.

  type StaticBlock struct {
      ...
      HeapItems   []bool
      _           struct{} `amino:"reserved"`   slot 8, was UnassignableNames
      Consts      []Name
      _           struct{} `amino:"reserved"`   slot 10, was Externs
      Parent      BlockNode
  }

The generated decoder gains a case 8: that reads slot 8 and throws the bytes away, so data written before this change still decodes. Consts stays 9 and Parent stays 11.

Nothing on disk today. Block nodes are held in memory only. SetBlockNode has its write to the backing store commented out, marked TODO. The reserved slot is there for the day that changes, not for data that exists now.

Concepts

TermWhat it means here
StaticBlockOne lexical scope, as the compiler sees it: the names declared in it and what the compiler knows about each.
NameSourceA record of how one name entered its block: the syntax node that declared it, and a kind such as NSFuncDecl.
uverseGno's built-in scope, the outermost one. Holds println, len, int and the rest.
aminoThe project's binary encoding. Fields are numbered by their position in the Go struct, so positions cannot be reused.
ADRArchitecture decision record. A short document, committed beside the code, saying what was decided and what was rejected.
