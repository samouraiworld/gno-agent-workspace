## Overview

A realm running an NFT collection holds a token, a private ledger, and a read view plus a ledger for every extension it wired up. This PR bundles them into two values: an `*NFT` the realm keeps to itself, carrying `Mint` and `Burn`, and a [`*Collection`](https://github.com/gnolang/gno/blob/6350eccaf/examples/gno.land/p/demo/tokens/grc721/collection/collection.gno#L10-13) · [↗](../../../../../.worktrees/gno-review-6074/examples/gno.land/p/demo/tokens/grc721/collection/collection.gno#L10) it publishes, carrying the token's read side and a tree of extension read views. The registry in [#6075](https://github.com/gnolang/gno/pull/6075) stores the second one. To make the published value buildable without trusting a caller, the core package changed shape: [`RegisterExtension`](https://github.com/gnolang/gno/blob/6350eccaf/examples/gno.land/p/demo/tokens/grc721/token.gno#L156) · [↗](../../../../../.worktrees/gno-review-6074/examples/gno.land/p/demo/tokens/grc721/token.gno#L156) now takes the hook set and the read view in one call, keeps them as a pair, and exposes `ExtensionKinds`, `ExtensionView` and `HasExtension` so the collection reads its own contents off the ledger.

**Verdict: REQUEST CHANGES** — the redesign closed every forgery path of the previous round, and the guard that used to sit in the collection package did not move into the core with the data: `RegisterExtension` stores a view without calling either of the two methods that would place it, and `ExtensionView.TokenID()` came out of this diff with no reader left anywhere in the repository (3 Warnings, 1 Nit, 2 Suggestions, 2 missing tests).

## Summary

`RegisterExtension` and `Collection` are the whole trust surface. `Wrap` now rejects a ledger that is not the token's, `NewCollection` takes no view from its caller, and the collection reads views back off the ledger, which removes every path a stranger had to plant one. What is left unchecked is the pair the issuer hands `RegisterExtension`: the view is filed under the hook's kind and never asked its own kind or its own token, so the only remaining way to get a wrong view into a genuine collection is the issuer's own slip, and nothing reports it. The second seam is that [`sync`](https://github.com/gnolang/gno/blob/6350eccaf/examples/gno.land/p/demo/tokens/grc721/collection/collection.gno#L31-41) · [↗](../../../../../.worktrees/gno-review-6074/examples/gno.land/p/demo/tokens/grc721/collection/collection.gno#L31) keeps a copy of the ledger's registry rather than reading it, which is what makes two of the three Warnings possible. Read [`token.gno:156-167`](https://github.com/gnolang/gno/blob/6350eccaf/examples/gno.land/p/demo/tokens/grc721/token.gno#L156-L167) · [↗](../../../../../.worktrees/gno-review-6074/examples/gno.land/p/demo/tokens/grc721/token.gno#L156) first, then [`collection.gno:31-41`](https://github.com/gnolang/gno/blob/6350eccaf/examples/gno.land/p/demo/tokens/grc721/collection/collection.gno#L31-L41) · [↗](../../../../../.worktrees/gno-review-6074/examples/gno.land/p/demo/tokens/grc721/collection/collection.gno#L31).
