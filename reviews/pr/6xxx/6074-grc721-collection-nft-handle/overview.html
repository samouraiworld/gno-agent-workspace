PR 6074: one handle for the issuer, one for everyone else

Explainer for gnolang/gno#6074, third of the GRC721 series. Generated by claude-opus-5. No review state on this page: Review files.

The problem it solves

After #6072 and #6073, a realm running an NFT collection is holding four or five loose values: the token, the private ledger, and a read view plus a ledger for each extension it attached. Anything it wants to publish has to be assembled by hand, and publishing the wrong one of those values gives away the right to mint. This PR bundles them into two handles, 130 lines of code plus 264 of tests.

HandleWhat it carriesWho may hold it
*Collection The token's read side and a tree of extension read views, keyed by kind. Anyone. There is no write method on it.
*NFT The collection above, plus the private ledger, plus Mint and Burn. The issuing realm alone, in an unexported variable.

How a realm uses it

var nft *collection.NFT   // unexported: this is the admin handle

func init(cur realm) {
    nft = collection.New("Punks", "PUNK", 0, cur)

    enum, _ := enumerable.NewEnumerable(nft.Ledger())
    meta, _ := metadata.NewMetadata(nft.Ledger())
    nft.Attach(enum).Attach(meta)
}

// what the realm publishes
func Collection() *collection.Collection { return nft.Collection() }

Attach records a read view for discovery and returns the NFT, so the calls chain. It does not wire anything: each extension was already wired to the ledger by its own constructor in #6073. Two views of the same kind, or a view built against a different token, are refused with a panic.

What the two constructors differ on

CallUse
New(name, symbol, id, rlm)Build the token and the handle together. Only works where a realm value is in hand, meaning init or a crossing function.
Wrap(token, ledger)Wrap a token and ledger a realm already built, for example one made before this package existed.

Reading a collection someone else published

col := somerealm.Collection()

if v, ok := col.Extension("royalty"); ok {
    roy := v.(*royalty.Royalty)          // the kind string is not a type, so assert
    receiver, amount, _ := roy.RoyaltyInfo("42", price)
}

The tree holds interface values, so the kind is a label rather than a guarantee. A reader that skips the type assertion is trusting whoever registered the view.

Concepts

Extension kindA short string naming an add-on: metadata, royalty, enumerable.
Read viewThe half of an extension with no write method, safe to publish.
Private ledgerThe value that carries the right to mint, burn and move tokens.
