PR 6074: one handle for the issuer, one for everyone else

Explainer for gnolang/gno#6074, third of the GRC721 series. Generated by claude-opus-5. No review state on this page: Review files.

TLDR

A realm that runs an NFT collection ends up holding a token, a private ledger and a read view for every add-on it wired up. This PR bundles them into two values: an *NFT the realm keeps to itself, and a *Collection it publishes. To make the second one buildable without trusting anybody, the core package now stores each add-on's read view next to its hooks, so the collection reads its own contents off the ledger instead of being handed them.

The problem it solves

After #6072 and #6073, a realm running an NFT collection is holding four or five loose values: the token, the private ledger, and a read view plus a ledger for each add-on it wired up. Anything it wants to publish has to be assembled by hand, and publishing the wrong one of those values gives away the right to mint. This PR bundles them into two handles, 135 lines of code plus 257 of tests, and changes 55 more lines in the core package to support it.

HandleWhat it carriesWho may hold it
*Collection The token's read side and a tree of add-on read views, keyed by a short name. Anyone. There is no write method on it.
*NFT The collection above, plus the private ledger, plus Mint and Burn. The issuing realm alone, in an unexported variable.

How a realm uses it

var (
    nft    *collection.NFT           // unexported: this is the admin handle
    ledger *grc721.PrivateLedger     // unexported: this is the mint authority
)

func init(cur realm) {
    nft, ledger = collection.New("Punks", "PUNK", 0, cur)

    enumerable.NewEnumerable(ledger)
    metadata.NewMetadata(ledger)
}

// what the realm publishes
func Collection() *collection.Collection { return nft.Collection() }

Each add-on constructor registers itself on the ledger and hands the ledger its own read view in the same call. Nothing else is wired: whoever holds the ledger supplies both halves in that one call, and there is no second step. nft.Collection() re-reads the ledger every time it is called, so the value a registry already stores picks up an add-on wired later.

What changed in the core package to make that work

Before this PR the ledger remembered only an add-on's hooks. It now remembers the pair, and exposes two read accessors so the collection can walk them.

BeforeAfter
RegisterExtension(ext) RegisterExtension(ext, view), view being nil for an add-on that publishes nothing
extensions []Extension extensions []registeredExtension, each a hooks-and-view pair
no way to ask what is registered ExtensionKinds(), ExtensionView(kind), HasExtension(kind)

Every existing caller of the one-argument form has to be edited, including the three add-on packages in this repo and one filetest.

The three ways to get a collection

CallUseDoes it pick up an add-on wired later
New(name, symbol, id, rlm)Build the token, the ledger and the handle together. Only works where a realm value is in hand, meaning init or a crossing function.Through the handle it returns, yes, and only through that one
Wrap(token, ledger)Wrap a token and ledger the realm already built, for example one made before this package existed. The pair is checked: the ledger has to be the token's own.Through the handle it returns, yes, and only through that one
NewCollection(ledger)Build the published value on its own, with no admin handle beside it.No

Reading a collection someone else published

col := somerealm.Collection()

if v, ok := col.Extension("royalty"); ok {
    roy := v.(*royalty.Royalty)          // the short name is not a type, so assert
    receiver, amount, _ := roy.RoyaltyInfo("42", price)
}

The tree holds interface values, so the short name is a label rather than a guarantee. A reader that skips the type assertion is trusting whoever registered the view.

Concepts

Extension kindA short string naming an add-on: metadata, royalty, enumerable.
Read viewThe half of an add-on with no write method, safe to publish.
HooksThe other half, which the ledger calls on every mint, transfer and burn.
Private ledgerThe value that carries the right to mint, burn and move tokens.
