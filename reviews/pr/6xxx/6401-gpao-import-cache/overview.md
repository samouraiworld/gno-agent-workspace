# gpao: keep genesis imports across verifications and skip settled packages
Generated by claude-opus-5-5.
PR: [gnolang/gno#6401](https://github.com/gnolang/gno/pull/6401)

## TLDR

The approval oracle used to download every package a submission imports, again, for each submission it checked, and it checked packages that were already live before asking whether they were. It now remembers the packages that came with the chain at launch and asks first whether a package is already live. Checking a submission against a large standard package costs one fetch per run instead of one per submission, and a catch-up over old blocks stops paying for verifications whose answer is already on chain.

## The genesis import cache

`importCache` maps a package path to the package source the node served. The daemon owns one, in `oracle.imports`, and keeps only a package that is public and was added at genesis: `closure` parses its `gnomod.toml` and keeps it when `[addpkg] height = 0` and it is not private. The reason is that `AddPackage` refuses an existing public path, so a public genesis package never changes for the life of the chain, and its size is fixed by the chain rather than by a submitter. A package added later is fetched again each time, because anyone can get one enabled and imported, and keeping it would let them grow the cache without bound. A private package can be redeployed under its path, and an absent one can be enabled, so neither is kept either.

## The import closure walk

Before spawning the child that checks a candidate, the daemon walks the candidate's imports with `walkImports`, the same walk the child uses, answering from the cache where it can and asking the node over `vm/qfile` otherwise. It collects the packages it found and the paths the node said it does not serve. The walk stops at the first transport fault and leaves the rest to the child, which still asks the node for whatever it is not handed and still decides what a missing import means.

## The import seed

The child, `gpao verify-one`, reads the candidate as one JSON document on stdin. It now reads an optional second document, an `importSeed` holding `Imports` and `Absent`, and loads both into its getter with `rpcGetter.seed`, so a warm genesis closure costs it no query. A driver that writes only the candidate keeps working: the child then fetches every import itself.

## Detecting a chain that started again

A dev chain can be reset under the same chain ID with a different genesis, and the cache would then serve the old one. The block reader in `run` watches for it: when a status poll reports a tip below the last height it has read, it sets the atomic flag `importsStale`, and the verifier goroutine empties the cache on its next `genesisImports` call. The flag is the only state the two goroutines share, so the cache itself needs no lock.

## The settled pre-check

`recordIfSettled` asks the node with `vm/qpkgmeta_json` whether the path is live with nothing pending, and when it is, records the candidate as already active and marks its bytes seen. `handleCandidate` now calls it before verification as well as after: the first call skips the work when catching up over blocks that were enabled long ago, and the second covers a package another approver activated while this one was being verified, so no fee is paid to be told it is live.

## Before and after

**Before:** each verification fetched its whole import closure from the node through the child's getter, and `handleCandidate` verified every unseen candidate before asking `isSettled`.

**After:** the daemon hands the child the genesis packages it already holds through the import seed, and `handleCandidate` asks `recordIfSettled` first, verifying only what is not yet live.

## What a user notices

- An operator sees fewer `vm/qfile` queries per verification once the genesis packages a candidate imports have been fetched once in the run; the cache lives in the process and is empty after a restart.
- A catch-up with `--start-height` over blocks already enabled logs that the package is already active and spends no verification time on it.
- A tip reported below the last read height logs an error naming the reset and drops the cache.

## What it leaves open

- The reset check reads tip heights only, so a chain started again that is already past the last read height when polled keeps the old cache; nothing ties the cache to a genesis hash yet.
- Packages a hard-forked genesis replays with `BlockHeight` metadata carry that height in `[addpkg]`, so the cache does not keep them.

## Words used here

| Name | What it is |
| --- | --- |
| `importCache` | Path to package source, kept by the daemon for public packages with `[addpkg] height = 0`. |
| `importSeed` | The optional second JSON document on the child's stdin: `Imports`, the packages found, and `Absent`, the paths the node does not serve. |
| `importsStale` | Atomic flag the block reader sets when the tip falls below the last read height; the verifier empties the cache when it sees it. |
