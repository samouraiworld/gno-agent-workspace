## Overview

gno's existing txtar lane runs one in-memory node, so no test in the tree can say "a validator went away and the chain carried on" or "a program outside the chain reacted to what the chain committed". The package-approver oracle in `contribs/gpao` is made entirely of the second kind, and no test drives its daemon against a chain: [`TestEstimateEnableAgainstARealChain`](https://github.com/gnolang/gno/blob/ddc5acfb9/contribs/gpao/endtoend_test.go#L34) · [↗](../../../../../.worktrees/gno-review-6135/contribs/gpao/endtoend_test.go#L34) is the only gpao test that boots a node, and it covers the gas estimate for `MsgEnablePackage`. This branch adds `misc/gnoe2e`, a Go module of its own that boots up to sixteen real `gnoland` processes per scenario from the enclosing checkout, exports each one's RPC address to the script, and lets the script stop a validator, restart it, and run the oracle beside the chain. Three scenarios ship with it, the last of which takes two validators of four away and asserts the oracle survives a chain that answers every query while committing nothing. Sixty-two of the sixty-five files sit under `misc/gnoe2e`. The other three are a new CI workflow, one comment in `ci-dir-misc.yml`, and `misc/gnoe2e/` added to the root `Makefile`'s `fix` loop.

**Verdict: APPROVE** — the module is sealed off from the chain, and what the branch gets wrong is a dropped struct field, an unenforced upper bound and one sentence of documentation (3 nits).

## Summary

The module is self-contained: `internal/cluster` owns genesis, ports and validator processes, `internal/integration` owns the txtar verbs and the `-- cluster --` parser, `internal/daemon` supervises one child, `internal/builder` builds `gnoland` and `gpao`, `internal/termlog` renders the CLI's log. The CLI and the `go test` driver both go through [`prepareSuite`](https://github.com/gnolang/gno/blob/ddc5acfb9/misc/gnoe2e/cmd_run.go#L299) · [↗](../../../../../.worktrees/gno-review-6135/misc/gnoe2e/cmd_run.go#L299) and [`prepareScenario`](https://github.com/gnolang/gno/blob/ddc5acfb9/misc/gnoe2e/cmd_run.go#L428) · [↗](../../../../../.worktrees/gno-review-6135/misc/gnoe2e/cmd_run.go#L428), so the two routes cannot drift. Every `-- cluster --` section is parsed and resolved against the defaults before any chain boots, at [`clusterspec.go:161-166`](https://github.com/gnolang/gno/blob/ddc5acfb9/misc/gnoe2e/internal/integration/clusterspec.go#L161-L166) · [↗](../../../../../.worktrees/gno-review-6135/misc/gnoe2e/internal/integration/clusterspec.go#L161-L166), which is what turns a misspelled key into a parse error rather than a failure partway through a suite.

Reading order: [`internal/cluster/cluster.go`](https://github.com/gnolang/gno/blob/ddc5acfb9/misc/gnoe2e/internal/cluster/cluster.go#L355) · [↗](../../../../../.worktrees/gno-review-6135/misc/gnoe2e/internal/cluster/cluster.go#L355) for how a cluster is assembled, then [`internal/integration/clusterspec.go`](https://github.com/gnolang/gno/blob/ddc5acfb9/misc/gnoe2e/internal/integration/clusterspec.go#L136) · [↗](../../../../../.worktrees/gno-review-6135/misc/gnoe2e/internal/integration/clusterspec.go#L136) for what a script may ask for, then [`internal/integration/commands.go`](https://github.com/gnolang/gno/blob/ddc5acfb9/misc/gnoe2e/internal/integration/commands.go#L233) · [↗](../../../../../.worktrees/gno-review-6135/misc/gnoe2e/internal/integration/commands.go#L233) for `eventually`, which is the one verb with non-obvious semantics, and last [`testdata/tour.txtar`](https://github.com/gnolang/gno/blob/ddc5acfb9/misc/gnoe2e/testdata/tour.txtar#L1-L17) · [↗](../../../../../.worktrees/gno-review-6135/misc/gnoe2e/testdata/tour.txtar#L1-L17), which reads as the dialect's specification.
