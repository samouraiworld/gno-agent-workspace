# PR 6165: seating govDAO T1 members from a shell script

Generated by claude-opus-5, effort xhigh.

## TLDR

`misc/govdao-scripts/extend-govdao-t1.sh` writes a short gno program to a temp
file and hands it to `gnokey maketx run`, which deploys it as a throwaway realm
and calls its `main`. That program asks
[`memberstore.Get`](https://github.com/gnolang/gno/blob/24d230fc9/examples/gno.land/r/gov/dao/v3/memberstore/memberstore.gno#L182)
for the govDAO member tree and writes T1 entries into it. Two properties of the
chain decide whether the write lands: which realms the govDAO proxy still lets
touch the member tree, and which realm owns the `Member` value being stored.

## The member tree and its gatekeeper

govDAO v3 keeps members in
[`r/gov/dao/v3/memberstore`](https://github.com/gnolang/gno/blob/24d230fc9/examples/gno.land/r/gov/dao/v3/memberstore/memberstore.gno),
a tier name to address to `*Member` tree. Anyone holding that tree can seat,
promote or remove a member with no vote, so `Get` is the gate:

```go
func Get(_ int, rlm realm) MembersByTier {
	if !rlm.IsCurrent() { ... }
	currealm := rlm.PkgPath()
	if !dao.InAllowedDAOs(currealm) {
		panic("this Realm is not allowed to get the Members data: " + currealm)
	}
	return members
}
```

[`InAllowedDAOs`](https://github.com/gnolang/gno/blob/24d230fc9/examples/gno.land/r/gov/dao/proxy.gno#L231-L240)
answers from a list the govDAO proxy stores. The list starts empty, and an
empty list means yes to everyone. That is deliberate: a fresh chain has no
members and therefore no way to vote one in, so genesis needs a window where a
plain transaction can write the first member directly.

## What a MsgRun's realm is called

`gnokey maketx run` does not run the file as the signer. It deploys the source
as a package whose path is built from the signer's address, at
[`keeper.go:1398`](https://github.com/gnolang/gno/blob/24d230fc9/gno.land/pkg/sdk/vm/keeper.go#L1398):

```go
memPkg.Path = chainDomain + "/e/" + msg.Caller.String() + "/run"
```

So a run signed by `g1jg8m...` reaches `memberstore.Get` as
`gno.land/e/g1jg8mtutu9khhfwc4nxmuhcpftf0pajdhfvsqf5/run`, never as an address
and never as a govDAO realm. Whether that path is on the allowed list is the
whole question, and the signer's own membership does not enter into it.

After the window closes, the only realm that may write the member tree is
`r/gov/dao/v3/impl`, and the way in is a proposal:
[`NewAddMemberRequest`](https://github.com/gnolang/gno/blob/24d230fc9/examples/gno.land/r/gov/dao/v3/impl/prop_requests.gno#L80)
builds one, the existing members vote, and execution does the write.

## Who allocated the `Member`

A second rule applies even inside the open window. A gno value belongs to the
realm that allocated it, and a realm may not allocate a type that another realm
owns. So these two lines are not interchangeable:

```go
&memberstore.Member{InvitationPoints: 3}   // the run realm allocates memberstore's type
memberstore.NewMember(3)                   // memberstore allocates its own type
```

The first aborts the transaction with `cannot allocate
gno.land/r/gov/dao/v3/memberstore.Member in realm gno.land/e/<signer>/run`. The
second is what the genesis scripts on
[pearl](https://github.com/gnolang/gno/blob/24d230fc9/misc/deployments/pearl.gno.land/transactions/base/bootstrap/govdao_prop1_pearl.gno#L44)
and
[test13](https://github.com/gnolang/gno/blob/24d230fc9/misc/deployments/test13.gno.land/transactions/base/bootstrap/govdao_prop1_test13.gno#L97)
already write.

Neither rule is visible to a static check. `gno lint` type-checks the file and
says nothing, because both are runtime facts the VM raises while the transaction
executes.

## Skipping an address that is already seated

[`SetMember`](https://github.com/gnolang/gno/blob/24d230fc9/examples/gno.land/r/gov/dao/v3/memberstore/types.gno#L75-L78)
refuses an address that sits in any tier, returning `ErrMemberAlreadyExists`
rather than moving it. A caller wanting to seat a list therefore has a choice
per entry: read the tier first with
[`GetMember`](https://github.com/gnolang/gno/blob/24d230fc9/examples/gno.land/r/gov/dao/v3/memberstore/types.gno#L94)
and skip, or let the error abort everything written so far in the same
transaction. Skipping also drops the signer's own entry for free, since a signer
authorised to make this call is by definition already seated.
