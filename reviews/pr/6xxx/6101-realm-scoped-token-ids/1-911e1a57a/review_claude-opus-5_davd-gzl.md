## Overview

A GRC20 token carries a text identifier that goes into every `Transfer`, `Approval`, `Mint` and `Burn` event it emits, and on master its tail is a number the creating realm picks, so one realm can give two independent ledgers the same identifier. This branch moves the number into the VM: a new native `runtime.NewRealmID()` returns `<realm-path>:<realm-time>` for the realm the machine is currently executing, and `grc20.NewToken` writes that string into the token. The number is drawn from `Realm.Time`, the same counter object persistence uses for object identities, so no two values a realm hands out ever repeat. Issuance is gated on a new execution-context flag, on for `AddPackage`, `EnablePackage`, `Call`, `Run` and `gno test`, off for queries. Thirty-five call sites drop the `seqid.ID` argument, and `grc20reg` swaps its identifier-prefix check for a new `Token.GetOriginRealm()` accessor.

**Verdict: REQUEST CHANGES** — the identifier and the token's origin realm are read from two different sources, and a call chain that puts a different realm in each produces a token whose events name one realm while the registry files it under another (3 Warnings, 1 Missing test, 2 Nits, 2 Suggestions).

## Summary

`Token.ID()` is what a token writes into the `token` attribute of its ledger events, and on master it is [`pkgPath + "." + symbol + "." + id.String()`](https://github.com/gnolang/gno/blob/d43dc0c50/examples/gno.land/p/demo/tokens/grc20/token.gno#L65) with the trailing `id` supplied by the caller, so a realm passing `0` twice announces two ledgers under one identity. That is [issue 6026](https://github.com/gnolang/gno/issues/6026). The branch replaces the whole string with [`runtime.NewRealmID()`](https://github.com/gnolang/gno/blob/911e1a57a/gnovm/stdlibs/chain/runtime/native.go#L45-L60) · [↗](../../../../../.worktrees/gno-review-6101/gnovm/stdlibs/chain/runtime/native.go#L45-L60), which bumps [`m.Realm.Time`](https://github.com/gnolang/gno/blob/911e1a57a/gnovm/stdlibs/chain/runtime/native.go#L55) · [↗](../../../../../.worktrees/gno-review-6101/gnovm/stdlibs/chain/runtime/native.go#L55), writes the realm back so the counter survives a transaction that saves nothing else, and returns `<path>:<n>`.

Uniqueness holds: `Realm.Time` is per realm, monotonic within a realm, and shared with [object finalisation](https://github.com/gnolang/gno/blob/911e1a57a/gnovm/pkg/gnolang/realm.go#L2033) · [↗](../../../../../.worktrees/gno-review-6101/gnovm/pkg/gnolang/realm.go#L2033), so a value handed to a token can never be handed to an object. Two realms cannot collide because the prefix is a package path. What the branch does not establish is that the prefix names the realm that made the token: `origRealm` comes from the `IsCurrent`-verified `rlm` argument and the prefix comes from `m.Realm`, and the two are separate readings of "who is calling".

Reading order: [`gnovm/stdlibs/chain/runtime/native.go`](https://github.com/gnolang/gno/blob/911e1a57a/gnovm/stdlibs/chain/runtime/native.go#L45-L60) · [↗](../../../../../.worktrees/gno-review-6101/gnovm/stdlibs/chain/runtime/native.go#L45-L60), the four keeper gates, [`token.gno`](https://github.com/gnolang/gno/blob/911e1a57a/examples/gno.land/p/demo/tokens/grc20/token.gno#L22-L60) · [↗](../../../../../.worktrees/gno-review-6101/examples/gno.land/p/demo/tokens/grc20/token.gno#L22-L60), [`grc20reg.gno:40`](https://github.com/gnolang/gno/blob/911e1a57a/examples/gno.land/r/demo/defi/grc20reg/grc20reg.gno#L40) · [↗](../../../../../.worktrees/gno-review-6101/examples/gno.land/r/demo/defi/grc20reg/grc20reg.gno#L40), then the four grc20 filetests, then the two new txtars, then the thirty-five call-site edits.

## Fix

`NewToken` drops its `id seqid.ID` parameter and assigns [`runtime.NewRealmID()`](https://github.com/gnolang/gno/blob/911e1a57a/examples/gno.land/p/demo/tokens/grc20/token.gno#L46) · [↗](../../../../../.worktrees/gno-review-6101/examples/gno.land/p/demo/tokens/grc20/token.gno#L46) instead, keeping `origRealm` as its own field for authorisation and display. `grc20reg.Register` drops the string-prefix test and compares [`token.GetOriginRealm()`](https://github.com/gnolang/gno/blob/911e1a57a/examples/gno.land/r/demo/defi/grc20reg/grc20reg.gno#L40) · [↗](../../../../../.worktrees/gno-review-6101/examples/gno.land/r/demo/defi/grc20reg/grc20reg.gno#L40) against the registering realm, which loses nothing: the key already carries the token's own symbol. The load-bearing constraint is that the counter is written inside the native rather than at finalisation, [`native.go:58`](https://github.com/gnolang/gno/blob/911e1a57a/gnovm/stdlibs/chain/runtime/native.go#L58) · [↗](../../../../../.worktrees/gno-review-6101/gnovm/stdlibs/chain/runtime/native.go#L58), because a transaction can issue an identifier and persist no object.
