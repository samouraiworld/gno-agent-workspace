## Overview

A GRC20 token carries a text identifier that goes into every `Transfer`, `Approval`, `Mint` and `Burn` event it emits, and on master its tail is a number the creating realm picks, so one realm can give two independent ledgers the same identifier. This branch moves the number into the VM: a new native `runtime.NewRealmID()` returns `<realm-path>:<realm-time>` for the realm the machine is currently executing, and `grc20.NewToken` writes that string into the token. The number is drawn from `Realm.Time`, the same counter object persistence uses for object identities, so no two values a realm hands out ever repeat. Issuance is gated on a new execution-context flag, on for `AddPackage`, `EnablePackage`, `Call`, `Run` and `gno test`, off for queries. Thirty-five call sites drop the `seqid.ID` argument, and `grc20reg` swaps its identifier-prefix check for a new `Token.GetOriginRealm()` accessor.

**Verdict: REQUEST CHANGES** — the identifier's prefix names the realm the VM borrowed into rather than the realm `NewToken` verified, the same read spends and rewrites a foreign realm's persistent counter, and the new gas row cannot survive a regeneration of the table it sits in (4 Warnings, 2 Missing tests, 5 Nits, 2 Suggestions).

The recommendation is that this pull request closes in favour of [#6139](https://github.com/gnolang/gno/pull/6139), which is a competing implementation of the same problem, [issue 6026](https://github.com/gnolang/gno/issues/6026), by a different mechanism. The two are mutually exclusive: `git merge-tree --write-tree 20d2a9f2e 011afff91` exits 1 with **19 conflicting files**, among them all four stdlib files, the `grc20` and `grc20reg` trees, and a modify/delete where #6139 deletes [`newtoken_event_filetest.gno`](https://github.com/gnolang/gno/blob/20d2a9f2e/examples/gno.land/p/demo/tokens/grc20/filetests/newtoken_event_filetest.gno#L1) · [↗](../../../../../.worktrees/gno-review-6101/examples/gno.land/p/demo/tokens/grc20/filetests/newtoken_event_filetest.gno#L1) that #6101 edits. ## Summary

`Token.ID()` is what a token writes into the `token` attribute of its ledger events, and on master it is [`pkgPath + "." + symbol + "." + id.String()`](https://github.com/gnolang/gno/blob/d43dc0c50/examples/gno.land/p/demo/tokens/grc20/token.gno#L65) with the trailing `id` supplied by the caller, so a realm passing `0` twice announces two ledgers under one identity. That is [issue 6026](https://github.com/gnolang/gno/issues/6026). The branch replaces the whole string with [`runtime.NewRealmID()`](https://github.com/gnolang/gno/blob/20d2a9f2e/gnovm/stdlibs/chain/runtime/native.go#L45-L60) · [↗](../../../../../.worktrees/gno-review-6101/gnovm/stdlibs/chain/runtime/native.go#L45-L60), which bumps [`m.Realm.Time`](https://github.com/gnolang/gno/blob/20d2a9f2e/gnovm/stdlibs/chain/runtime/native.go#L55) · [↗](../../../../../.worktrees/gno-review-6101/gnovm/stdlibs/chain/runtime/native.go#L55), writes the realm back so the counter survives a transaction that saves nothing else, and returns `<path>:<n>`.

The collision issue 6026 reports is closed: `Realm.Time` is per realm, monotonic within a realm, and shared with [object finalisation](https://github.com/gnolang/gno/blob/20d2a9f2e/gnovm/pkg/gnolang/realm.go#L2033) · [↗](../../../../../.worktrees/gno-review-6101/gnovm/pkg/gnolang/realm.go#L2033), so a value handed to a token can never be handed to an object, and two realms cannot collide because the prefix is a package path. What the branch does not establish is the stronger property its body, its ADR and one of its own filetests all assert on top of that, that the prefix names the token's own realm. `m.Realm` is the realm the VM borrowed into for storage, and it is the one value this native reads: [`NewRealmID`](https://github.com/gnolang/gno/blob/20d2a9f2e/gnovm/stdlibs/chain/runtime/native.go#L49) · [↗](../../../../../.worktrees/gno-review-6101/gnovm/stdlibs/chain/runtime/native.go#L49) is the only realm-scoped native in `gnovm/stdlibs/` that names a realm from `m.Realm.Path`, while every other identity-bearing one goes through [`execctx.CurrentRealm`](https://github.com/gnolang/gno/blob/20d2a9f2e/gnovm/stdlibs/internal/execctx/realm.go#L96-L98) · [↗](../../../../../.worktrees/gno-review-6101/gnovm/stdlibs/internal/execctx/realm.go#L96-L98), the crossing-identity walk, [`chain/params.pkey`](https://github.com/gnolang/gno/blob/20d2a9f2e/gnovm/stdlibs/chain/params/params.go#L106) · [↗](../../../../../.worktrees/gno-review-6101/gnovm/stdlibs/chain/params/params.go#L106) being the neighbour to compare against.

Reading order: [`gnovm/stdlibs/chain/runtime/native.go`](https://github.com/gnolang/gno/blob/20d2a9f2e/gnovm/stdlibs/chain/runtime/native.go#L45-L60) · [↗](../../../../../.worktrees/gno-review-6101/gnovm/stdlibs/chain/runtime/native.go#L45-L60), the two borrow rules in [`machine.go:2567-2586`](https://github.com/gnolang/gno/blob/20d2a9f2e/gnovm/pkg/gnolang/machine.go#L2567-L2586) · [↗](../../../../../.worktrees/gno-review-6101/gnovm/pkg/gnolang/machine.go#L2567-L2586), the four keeper gates, [`token.gno`](https://github.com/gnolang/gno/blob/20d2a9f2e/examples/gno.land/p/demo/tokens/grc20/token.gno#L22-L60) · [↗](../../../../../.worktrees/gno-review-6101/examples/gno.land/p/demo/tokens/grc20/token.gno#L22-L60), [`grc20reg.gno:40`](https://github.com/gnolang/gno/blob/20d2a9f2e/examples/gno.land/r/demo/defi/grc20reg/grc20reg.gno#L40) · [↗](../../../../../.worktrees/gno-review-6101/examples/gno.land/r/demo/defi/grc20reg/grc20reg.gno#L40), then the four grc20 filetests, then the one new [`grc20_id_persists_cross_realm.txtar`](https://github.com/gnolang/gno/blob/20d2a9f2e/gno.land/pkg/integration/testdata/grc20_id_persists_cross_realm.txtar#L1) · [↗](../../../../../.worktrees/gno-review-6101/gno.land/pkg/integration/testdata/grc20_id_persists_cross_realm.txtar#L1) at +49 and the single assertion line each of four existing archives gains, then the thirty-five call-site edits.

## Fix

`NewToken` drops its `id seqid.ID` parameter and assigns [`runtime.NewRealmID()`](https://github.com/gnolang/gno/blob/20d2a9f2e/examples/gno.land/p/demo/tokens/grc20/token.gno#L46) · [↗](../../../../../.worktrees/gno-review-6101/examples/gno.land/p/demo/tokens/grc20/token.gno#L46) instead, keeping `origRealm` as its own field for authorisation and display. `grc20reg.Register` drops the string-prefix test and compares [`token.GetOriginRealm()`](https://github.com/gnolang/gno/blob/20d2a9f2e/examples/gno.land/r/demo/defi/grc20reg/grc20reg.gno#L40) · [↗](../../../../../.worktrees/gno-review-6101/examples/gno.land/r/demo/defi/grc20reg/grc20reg.gno#L40) against the registering realm, which loses nothing: the key already carries the token's own symbol. The load-bearing constraint is that the counter is written inside the native rather than at finalisation, [`native.go:58`](https://github.com/gnolang/gno/blob/20d2a9f2e/gnovm/stdlibs/chain/runtime/native.go#L58) · [↗](../../../../../.worktrees/gno-review-6101/gnovm/stdlibs/chain/runtime/native.go#L58), because a transaction can issue an identifier and persist no object.
