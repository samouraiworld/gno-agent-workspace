# Gno rejects `import . "pkg"`, now written down and tested
Generated by claude-opus-5-5.

## TLDR

Gno has always refused dot imports. This change documents the refusal, replaces a forgotten test that claimed the opposite with one that checks the refusal, and gives both refusal sites the same message.

## What it is for

A Go file can write `import . "strings"` and call `HasPrefix` with no `strings.` in front. Gno panics on that line during preprocessing, but the compatibility page never said so, and an old test file in `gnovm/tests/backup/` still showed a dot import printing output. No test runner reads that directory, so the file never failed.

## How it works today

Before the change, two places in `gnovm/pkg/gnolang/preprocess.go` reject a dot import:

| Site | When it runs | Message before |
| --- | --- | --- |
| `initStaticBlocks2` | first, while names are reserved for each file | `dot imports not allowed in gno` |
| `tryPredefine` | later, when imports are defined | `dot imports not allowed in Gno` |

The first site always fires, so users only ever see the lowercase message.

## What the change does

- `docs/resources/go-gno-compatibility.md`: the `import` row now reads `full (except .)`, and a note explains the ban. A dot import would pull every exported name of the dependency into the file, and a deployed package cannot change while its dependencies can add names, so a later export could clash with an existing importer.
- `gnovm/tests/backup/import2.gno` is deleted. It imported `fmt`, which Gno does not ship.
- `gnovm/tests/files/import2.gno` is added. It dot-imports the real `strings` package and expects `main/import2.gno:3:8-19: dot imports not allowed in gno`.
- After the change, both sites print the lowercase message, and a comment in `initStaticBlocks2` records the reason, pointing at issue gnolang/gno#6076.

## Concepts

- **Filetest**: a `.gno` file under `gnovm/tests/files` whose trailing `// Output:` or `// Error:` comment is the expected result; `TestFiles` in `gnovm/pkg/gnolang/files_test.go` runs every one.
- **Preprocessing**: the pass that resolves names and types before the VM runs anything; a panic there becomes an error with a file position.
