# PR 6192: the two package paths a GRC20 token stores

Explainer for [PR 6192](https://github.com/gnolang/gno/pull/6192), generated by
claude-opus-5, xhigh review.

## TLDR

A token stores two different package paths when its realm creates it under a
`realm.Sub` identity: `origRealm`, the host with the subpath cut off, and the
string `Token.ID()` returns, which keeps the subpath. Six doc comments in
[`p/nt/grc20/v0`](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/p/nt/grc20/v0/token.gno#L13-L17)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/p/nt/grc20/v0/token.gno#L13)
and
[`p/nt/grc721/v0`](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/p/nt/grc721/v0/types.gno#L60)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/p/nt/grc721/v0/types.gno#L60)
state that pair wrongly: they cut the path on `:` where the VM cuts on `#`,
they build the id out of `origRealm`, and they name `Token.ID()` as the
registry key. The branch rewrites those comments and changes no code.

## A sub-realm is a second identity for the same realm

[`cur.Sub("vault")`](https://github.com/gnolang/gno/blob/37e2ce18b/gnovm/pkg/gnolang/uverse.go#L1700-L1718)
· [↗](../../../../.worktrees/gno-review-6192/gnovm/pkg/gnolang/uverse.go#L1700)
gives a realm a second identity without a second package. The minted value's
package path is
[the host path, a `#`, and the subpath run together](https://github.com/gnolang/gno/blob/37e2ce18b/gnovm/pkg/gnolang/uverse.go#L1732)
· [↗](../../../../.worktrees/gno-review-6192/gnovm/pkg/gnolang/uverse.go#L1732),
and its address is
[derived from that joined string](https://github.com/gnolang/gno/blob/37e2ce18b/gnovm/pkg/gnolang/uverse.go#L1766-L1767)
· [↗](../../../../.worktrees/gno-review-6192/gnovm/pkg/gnolang/uverse.go#L1766)
and not from the host path, so the sub identity has an address of its own. A
probe realm run at the reviewed head answers
`g1g0sqwywmnw75g2zlkfcywz45ds3lguy3uedacq` for its host identity and
`g1kkjaduylaksy6tgcrkagxpt439m40l0mlqg6lw` for `vault`.

No real package path can carry a `#`:
[`ValidateMemPackageAny` rejects one](https://github.com/gnolang/gno/blob/37e2ce18b/gnovm/pkg/gnolang/mempackage.go#L1183-L1184)
· [↗](../../../../.worktrees/gno-review-6192/gnovm/pkg/gnolang/mempackage.go#L1183).
That rejection is why the character can mark a synthesized path without
colliding with a real one, and both sides of the VM boundary hold it as a
constant,
[`subRealmSep` in the VM](https://github.com/gnolang/gno/blob/37e2ce18b/gnovm/pkg/gnolang/uverse.go#L250-L255)
· [↗](../../../../.worktrees/gno-review-6192/gnovm/pkg/gnolang/uverse.go#L250)
and
[the same name in the `chain` stdlib](https://github.com/gnolang/gno/blob/37e2ce18b/gnovm/stdlibs/chain/address.gno#L10-L13)
· [↗](../../../../.worktrees/gno-review-6192/gnovm/stdlibs/chain/address.gno#L10).

Cutting a path back apart is
[`chain.SplitPkgSubPath`](https://github.com/gnolang/gno/blob/37e2ce18b/gnovm/stdlibs/chain/address.gno#L33-L39)
· [↗](../../../../.worktrees/gno-review-6192/gnovm/stdlibs/chain/address.gno#L33),
a `strings.Cut` on that constant. A path holding no `#` comes back whole with
`ok` false, so one call handles a host path and a synthesized one alike.
Anything off-chain that needs the address without asking the host recomputes it
with
[`chain.DerivePkgSubAddr`](https://github.com/gnolang/gno/blob/37e2ce18b/gnovm/stdlibs/chain/address.gno#L21-L30)
· [↗](../../../../.worktrees/gno-review-6192/gnovm/stdlibs/chain/address.gno#L21),
which joins and derives the same way.

## `guardHome`, the teller that only works at home

[`CallerTeller`](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/p/nt/grc20/v0/tellers.gno#L24-L36)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/p/nt/grc20/v0/tellers.gno#L24)
returns a teller that debits whoever crossed into the realm holding it. Inside
the token's own realm that is the point. Anywhere else it is a confused deputy:
a foreign realm holding the same value charges its own callers against a ledger
they never chose.
[Keeping the ledger private does not close that door on its own](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/p/nt/grc20/v0/tellers.gno#L12-L23)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/p/nt/grc20/v0/tellers.gno#L12),
because a realm that builds a teller legally can then export the value.

[`guardHome`](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/p/nt/grc20/v0/tellers.gno#L152-L161)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/p/nt/grc20/v0/tellers.gno#L152)
is what makes an exported teller inert. Every write compares the invoking
realm's path against the token's `origRealm` and returns
[`ErrForeignCallerTeller`](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/p/nt/grc20/v0/types.gno#L127)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/p/nt/grc20/v0/types.gno#L127)
when they differ.

Both sides of that comparison lose their subpath first.
[The invoking path is cut in `guardHome`](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/p/nt/grc20/v0/tellers.gno#L156)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/p/nt/grc20/v0/tellers.gno#L156)
and
[the stored path is cut in `NewToken`](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/p/nt/grc20/v0/token.gno#L64)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/p/nt/grc20/v0/token.gno#L64),
so a token minted under `cur.Sub("vault")` still answers to the host realm, and
a host's sub-realms are not turned away.
[Storing the raw path instead would lock the host out of its own token](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/p/nt/grc20/v0/token.gno#L60-L63)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/p/nt/grc20/v0/token.gno#L60).
grc721 carries
[the same cut in its guard](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/p/nt/grc721/v0/tellers.gno#L136)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/p/nt/grc721/v0/tellers.gno#L136)
and
[in its constructor](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/p/nt/grc721/v0/token.gno#L45)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/p/nt/grc721/v0/token.gno#L45).

## `Token.ID()` keeps the path `origRealm` throws away

`NewToken` writes two fields from one argument.
[`origRealm` takes the cut host](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/p/nt/grc20/v0/token.gno#L64)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/p/nt/grc20/v0/token.gno#L64);
[`id` takes the raw path](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/p/nt/grc20/v0/token.gno#L67)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/p/nt/grc20/v0/token.gno#L67),
joined to the symbol and the sequence id. At a host realm the two paths are
equal. Under a sub identity they differ, and `Token.ID()` is the one that still
says `vault`.

[`r/nt/grc20reg/v0`](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/r/nt/grc20reg/v0/grc20reg.gno#L15)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/r/nt/grc20reg/v0/grc20reg.gno#L15)
is gno.land's GRC20 registry, and it keys on neither of those two fields
directly.
[`Register`](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/r/nt/grc20reg/v0/grc20reg.gno#L32-L58)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/r/nt/grc20reg/v0/grc20reg.gno#L32)
reads
[the path the calling realm presents](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/r/nt/grc20reg/v0/grc20reg.gno#L39)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/r/nt/grc20reg/v0/grc20reg.gno#L39),
[joins it to the symbol](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/r/nt/grc20reg/v0/grc20reg.gno#L40)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/r/nt/grc20reg/v0/grc20reg.gno#L40)
with
[`fqname.Construct`](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/p/nt/fqname/v0/fqname.gno#L51-L57)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/p/nt/fqname/v0/fqname.gno#L51),
and
[requires `Token.ID()` to start with that key and a dot](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/r/nt/grc20reg/v0/grc20reg.gno#L41-L45)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/r/nt/grc20reg/v0/grc20reg.gno#L41).
The key is therefore `Token.ID()` minus its trailing sequence id, and the
registering frame has to be the frame that created the token. A token minted
under `cur.Sub("vault")` and registered from the host frame fails the prefix
check and panics with `grc20reg: token must be registered from its own realm`.

## The values, side by side

The four rows come from a run, not from reading the source: a probe realm
created one token each way at the reviewed head and printed what came back.

| | created at the host realm | created under `cur.Sub("vault")` |
| --- | --- | --- |
| `rlm.PkgPath()` handed to `NewToken` | `gno.land/r/demo/probe6192` | `gno.land/r/demo/probe6192#vault` |
| `origRealm` stored on the `Token` | `gno.land/r/demo/probe6192` | `gno.land/r/demo/probe6192` |
| `Token.ID()` | `gno.land/r/demo/probe6192.HOSTA.0000000` | `gno.land/r/demo/probe6192#vault.SUBB.0000000` |
| `grc20reg` key, registered from that same frame | `gno.land/r/demo/probe6192.HOSTA` | `gno.land/r/demo/probe6192#vault.SUBB` |

Three more results from the probe. The sub-created token's home teller,
invoked from the host frame, is accepted, which is the `origRealm` cut doing
its job. The grc721 constructor produces
`gno.land/r/demo/probe6192#vault.SUBN.0000000` from the same sub identity.
Registering the sub-created token from the host frame panics, in a second run,
because the key that frame builds is `gno.land/r/demo/probe6192.SUBB` while the
id starts with `gno.land/r/demo/probe6192#vault.SUBB`.

```go
// examples/gno.land/r/demo/probe6192/gnomod.toml
// module = "gno.land/r/demo/probe6192"

package probe6192

import (
	"chain"

	"gno.land/p/nt/grc20/v0"
	"gno.land/p/nt/grc721/v0"
	"gno.land/p/nt/seqid/v0"
	"gno.land/r/nt/grc20reg/v0"
)

// HostCase: a token created at the host realm.
func HostCase(cur realm) {
	pkgPath := cur.PkgPath()
	orig, _, _ := chain.SplitPkgSubPath(pkgPath)
	tok, _ := grc20.NewToken("Host token", "HOSTA", 4, seqid.ID(0), cur)
	key := grc20reg.Register(cross(cur), tok, "")
	println("host addr:", cur.Address())
	println("host pkgPath:", pkgPath)
	println("host origRealm:", orig)
	println("host ID:", tok.ID())
	println("host regkey:", key)
}

// SubCase: a token created under cur.Sub("vault").
func SubCase(cur realm) {
	sub := cur.Sub("vault")
	pkgPath := sub.PkgPath()
	orig, _, _ := chain.SplitPkgSubPath(pkgPath)
	tok, ledger := grc20.NewToken("Sub token", "SUBB", 4, seqid.ID(0), sub)
	println("sub addr:", sub.Address())
	println("sub pkgPath:", pkgPath)
	println("sub origRealm:", orig)
	println("sub ID:", tok.ID())
	// guardHome: the home teller of a sub-created token, invoked from the
	// host frame, is accepted because origRealm was stripped.
	teller := ledger.CallerTeller()
	err := teller.Approve(0, cur, chain.PackageAddress("gno.land/r/demo/spender"), 1)
	println("sub home teller from host frame, accepted:", err == nil)
	println("sub regkey from sub frame:", grc20reg.Register(cross(sub), tok, ""))
}

// NFTCase: grc721 builds Token.ID() the same way.
func NFTCase(cur realm) {
	sub := cur.Sub("vault")
	tok, _ := grc721.NewToken("Sub NFT", "SUBN", seqid.ID(0), sub)
	println("nft sub pkgPath:", sub.PkgPath())
	println("nft sub ID:", tok.ID())
}

// SubRegisterFromHost registers a sub-created token from the host frame.
func SubRegisterFromHost(cur realm) {
	sub := cur.Sub("vault")
	tok, _ := grc20.NewToken("Sub token", "SUBB", 4, seqid.ID(0), sub)
	println("sub ID:", tok.ID())
	println("host-frame regkey:", grc20reg.Register(cross(cur), tok, ""))
}
```

## What the change corrects

### The separator is `#`, not `:`

One sentence sat in three places at 5d7d8f5f9:
[grc20's guard comment](https://github.com/gnolang/gno/blob/5d7d8f5f9/examples/gno.land/p/nt/grc20/v0/tellers.gno#L144-L145),
[grc721's guard comment](https://github.com/gnolang/gno/blob/5d7d8f5f9/examples/gno.land/p/nt/grc721/v0/tellers.gno#L123-L124)
and
[grc721's constructor comment](https://github.com/gnolang/gno/blob/5d7d8f5f9/examples/gno.land/p/nt/grc721/v0/token.gno#L40).
Before, the grc20 copy:

```go
// The host is compared after stripping any ":subpath" synthesized by
// realm.Sub, so the token's own sub-realms are not falsely rejected.
```

After, at 37e2ce18b:

```go
// The host is compared after stripping any "#subpath" synthesized by
// realm.Sub, so the token's own sub-realms are not falsely rejected.
```

The code cuts on
[`subRealmSep`, which is `"#"`](https://github.com/gnolang/gno/blob/37e2ce18b/gnovm/pkg/gnolang/uverse.go#L255)
· [↗](../../../../.worktrees/gno-review-6192/gnovm/pkg/gnolang/uverse.go#L255).
A reader who writes their own split from the old comment cuts on a character
the path never contains and strips nothing.

### `Token.ID()` is built from the raw path

Before, at 5d7d8f5f9, in
[the `NewToken` godoc](https://github.com/gnolang/gno/blob/5d7d8f5f9/examples/gno.land/p/nt/grc20/v0/token.gno#L15-L16),
[the `ID()` godoc](https://github.com/gnolang/gno/blob/5d7d8f5f9/examples/gno.land/p/nt/grc20/v0/token.gno#L135)
and
[the grc721 field comment](https://github.com/gnolang/gno/blob/5d7d8f5f9/examples/gno.land/p/nt/grc721/v0/types.gno#L60):

```go
// p/nt/grc20/v0/token.gno:15-16
// and rlm.PkgPath() — the calling realm itself — becomes the Token's
// origRealm. Token.ID() returns origRealm + "." + symbol + "." + id.

// p/nt/grc20/v0/token.gno:135
// It is composed of the original realm, the symbol, and the provided id.

// p/nt/grc721/v0/types.gno:60
	id     string // origRealm + "." + symbol + "." + id
```

After, at 37e2ce18b:

```go
// p/nt/grc20/v0/token.gno:15-17
// and rlm.PkgPath() — the calling realm itself, with any realm.Sub subpath
// stripped — becomes the Token's origRealm. Token.ID() keeps the raw
// rlm.PkgPath(), and returns it + "." + symbol + "." + id.

// p/nt/grc20/v0/token.gno:137-138
// It is composed of the creating realm's raw pkgpath — including any
// realm.Sub subpath, unlike origRealm — the symbol, and the provided id.

// p/nt/grc721/v0/types.gno:60
	id     string // raw creation pkgpath + "." + symbol + "." + id
```

The constructor joins
[the raw `pkgPath`](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/p/nt/grc20/v0/token.gno#L67)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/p/nt/grc20/v0/token.gno#L67),
so the measured `gno.land/r/demo/probe6192#vault.SUBB.0000000` is what the new
wording predicts and the old one does not. The two descriptions diverged at
[acd01fa29](https://github.com/gnolang/gno/commit/acd01fa29b6caa7afa0f270c606aa266bcad5fce),
which introduced the `origRealm` cut and left the ids alone.
[grc721's constructor comment already said this](https://github.com/gnolang/gno/blob/5d7d8f5f9/examples/gno.land/p/nt/grc721/v0/token.gno#L43-L44)
while its own field comment said the opposite.

### The registry key is the id without its trailing sequence

Before, at 5d7d8f5f9, in
[the `NewToken` godoc](https://github.com/gnolang/gno/blob/5d7d8f5f9/examples/gno.land/p/nt/grc20/v0/token.gno#L32):

```go
// grc20reg.Register(cross(cur), Token, slug). The registry key is Token.ID().
```

After, at 37e2ce18b:

```go
// grc20reg.Register(cross(cur), Token, slug). The registry key is the
// rlmPath.symbol prefix of Token.ID(), without its trailing id.
```

The registry says the same thing about itself in
[its own comment](https://github.com/gnolang/gno/blob/37e2ce18b/examples/gno.land/r/nt/grc20reg/v0/grc20reg.gno#L27-L31)
· [↗](../../../../.worktrees/gno-review-6192/examples/gno.land/r/nt/grc20reg/v0/grc20reg.gno#L27),
and the measured key `gno.land/r/demo/probe6192.HOSTA` is the id
`gno.land/r/demo/probe6192.HOSTA.0000000` without its last segment. One thing
the new wording leaves for the reader: `rlmPath` is the path of whichever frame
calls `Register`, so the prefix holds only where that frame is also the one
that created the token.
