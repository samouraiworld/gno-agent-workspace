Integration scripts move next to the code they test

Overview of gnolang/gno#6032, written by claude-opus-5.

TLDR. A .txtar is an integration script: it boots a node and drives it through gnokey. Every one of them used to live in a single folder, gno.land/pkg/integration/testdata/, however far that was from the realm it exercises.

This change lets a script sit in the realm's own directory, teaches the test runner to walk both places, and makes an empty root a hard failure so a mis-set GNOROOT cannot drop a whole root in silence. Eleven scripts move. Four tools that read the old folder follow them.

Words used here

.txtarA text archive: a script at the top, then files, each introduced by a -- name -- line. The test runner writes the files into a temp directory and runs the script over them.
testscriptThe library that runs those archives. It names each subtest after the file's base name alone, so wugnot.txtar becomes TestTestdata/wugnot wherever it sits.
GNOROOTAn environment variable naming the gno source tree. Whatever it points at is where the examples are read from.

The base names have to stay unique across both roots, because the subtest name never says which root a script came from. A collision is reported at discovery and fails the whole suite, rather than being silently disambiguated as render and render#1.

Which folder a new script belongs in

The script is aboutIt goesExample

the VM, the node, or gnokeygno.land/pkg/integration/testdata/gnokey_query.txtar

Either way the same test runs it, and go test ./gno.land/pkg/integration/ -run TestTestdata/wugnot selects it without the caller knowing where it lives.
