PR 6075: a phone book for NFT collections

Explainer for gnolang/gno#6075, last of the GRC721 series. Generated by claude-opus-5. No review state on this page: Review files.

TLDR

A realm where any other realm can list its NFT collection, so wallets and marketplaces find it by name instead of by import. The entry is filed under the listing realm's own path and its token's symbol, and the realm can take it back down. What is stored is the live collection, so what the pages show is whatever it holds when the page is asked for.

What it adds

A realm at r/demo/defi/grc721reg, the counterpart of r/demo/defi/grc20reg, which does the same for fungible tokens. 296 lines of realm code and 538 of tests.

The key

An entry is filed under the listing realm's path plus the token's own symbol. Neither half is the caller's to choose: the path comes from the live crossing frame, the symbol from the token.

gno.land/r/alice/punks.PUNK

Registration then checks that the collection was issued by that realm. A token's id is its creating realm, its symbol and a sequence number joined by dots, so the registry asks whether the id starts with the key. That one prefix check covers both halves, and it holds a collection to a single entry.

A slug argument survives, but only as a field on the event, and only letters, digits, underscore and hyphen are accepted, up to 128 characters.

What a caller gets back

CallAnswer
Register(cur, col, slug)The key it filed the collection under.
Unregister(cur, symbol)The key it removed. A realm can only reach its own, since the key carries its path.
Get(key)The collection, or nil.
MustGet(key)The collection, or a panic.
GetToken(key)Just the token's read side.
GetExtension(key, kind)One extension read view, plus whether it was there.
GetRegistry()The whole tree behind a read-only wrapper.

The trade the package doc names

grc20reg stores a concrete *grc20.Token, so what comes out is what the type says. This registry stores extension views as interface values, which is what lets it hold add-on kinds it does not import, including kinds nobody has written yet. The cost is that the type check moves to the reader: a kind is a label chosen by whoever listed the entry, so a consumer asserts the concrete type before trusting it.

The two pages it renders

The index, one line per collection, twenty to a page:

- Gno Punks - gno.land/r/alice/punks - metadata royalty - info
- Sky Cats - gno.land/r/bob/cats - core only - info

And a page per collection, reached by putting the key after the colon in the URL:

Gno Punks
- symbol: PUNK
- realm: gno.land/r/alice/punks
- total supply: 1024
- extensions: metadata royalty

Both pages read the collection live, so the supply shown is the supply at the moment the page is asked for.

What the pages refuse to let a listing realm decide

Anyone may list, and every visitor pays for what is listed, so four ceilings sit between a listing realm and the index.

CeilingValueWhat it bounds
pageSize20Entries one index render walks. The page size query parameter is deliberately left unset, so a visitor cannot widen it either.
maxBadges8Add-on labels printed per line, the rest replaced by an ellipsis.
maxKindLen64Characters of one label, both at listing time and again at render time, since the set stays live.
maxEventKinds16Labels the register event carries, checked in the registry so an oversized set fails with its name on it rather than the event's.

A label is text the listing realm chose, so it reaches the page through md.InlineCode, which folds line breaks, strips invisible and direction-changing characters, and picks a fence wider than any run of backticks inside the label.

Listing a collection, end to end

var (
    nft    *collection.NFT
    ledger *grc721.PrivateLedger
)

func init(cur realm) {
    nft, ledger = collection.New("Gno Punks", "PUNK", 0, cur)

    meta, _ := metadata.NewMetadata(ledger)
    nft.Attach(meta)

    grc721reg.Register(cross(cur), nft.Collection(), "")
}

The call emits a register event carrying the key, the token id, the realm path, the slug, the symbol and one attribute per add-on label, which is what an indexer follows to keep its own copy in step. Unregister emits the matching unregister.
