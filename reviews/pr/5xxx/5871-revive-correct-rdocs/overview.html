Reviving r/docs

Explainer for gnolang/gno PR 5871, generated by claude-opus-5.

TLDR

Thirty documentation realms were parked in examples/quarantined/ and are moved back into the live tree, corrected on the way. Two kinds of correction dominate: caller-identity checks that the interrealm v2 runtime already guarantees are deleted, and four statements about how gnoweb renders markdown are replaced with what the renderer actually does.

The realms under gno.land/r/docs/ are the pages a newcomer reads first, so what they teach is copied into other people's contracts. That is why a documentation move gets read as a behaviour change.

What quarantine was

examples/gno.land/ is the set of packages a new chain deploys at genesis. When the test-13 package set was fixed, everything outside it was swept into examples/quarantined/, which still compiles and still runs its tests but is not deployed. The r/docs tree went with it. This change moves thirty units back, with git mv, so each file keeps its history. One realm, charts, stays in quarantine, and three are deleted.

Concept: which realm value needs checking

A Gno function whose first parameter is a realm is a crossing function: another realm reaches it by writing other.F(cross(cur)), and the runtime mints a fresh capability token for that frame. The token answers Previous() with the caller and IsCurrent() with whether it is the live frame's own token.

The token minted for the frame is by construction the live one, so testing it tells you nothing. A realm value handed in as a second parameter is different: the caller chose that value and can pass something derived, cur.Previous() being the obvious one, so testing it is the whole defence.

func F(cur realm) {                    // cur is minted here, per frame
    cur.IsCurrent()                    // always true — nothing to learn
    addr := cur.Previous().Address()   // the immediate caller
}

func H(_ int, rlm realm) {             // _ int keeps rlm out of first place,
    if !rlm.IsCurrent() {              // so this is a plain call, not a crossing
        panic("rlm is not the current realm")
    }                                  // without the check, a caller passes
    addr := rlm.Previous().Address()   // cur.Previous() and forges identity
}

The change deletes the first-cur checks across the revived realms, keeps the one on the secondary parameter in the crossing realm and teaches it as the case that counts, and rewrites the same rule in AGENTS.md and three files under docs/resources/.

The rule has a fifth copy, and it runs

misc/audit-pattern-harness merged the day before this change's base. It is a set of heuristic text-scan rules, each with a vulnerable and a fixed fixture, and one of them, current-guard, flagged any .Previous() not preceded by .IsCurrent() in the same function. Its fixture pair was a crossing function reading its own first cur, without the guard and with it, which is the arrangement the four prose documents above reverse. This change rewrites the rule to match them: it now flags a secondary rlm realm parameter read before that parameter's own IsCurrent(), and exempts a first-position cur. Both fixtures take the _ int, rlm realm shape, and five other fixtures that opened with the redundant first-cur check lose it.

Which parameter is worth checking is settled by what the VM accepts. A crossing function's first argument may only be the literal cur or cross(name), the preprocessor rejects anything else in that position, and cross checks at runtime that the name it was handed is the live frame's own token. So there is no expression a caller can write that reaches such a function with a first cur whose IsCurrent() is false.

The related fix in soliditypatterns/ownable

Separate from the deletions, one realm authenticated through a stack walk. The page also gains the mention rules it never stated: @name is auto-linked to /u/{name} for three to ninety letters, digits and underscores, a bech32 address the same way, and an email address not at all, because the parser requires a space or a line start before the @.

Two behaviour fixes inside the realms

MiniSocial v2's edit window did not measure time

A post can be edited for ten minutes after it is written. The check compared the post's own updatedAt against its createdAt plus ten minutes, and both fields are written with the same value when the post is created, so a post that was never edited passed the check however old it was. The window now compares the current block time against the creation time.

// before: compares the post against itself
if post.updatedAt.After(post.createdAt.Add(time.Minute * 10))

// after: compares now against the post
if time.Now().After(post.createdAt.Add(10 * time.Minute))

Reading one balance

The banker demo read its own ugnot balance with GetCoins(addr).AmountOf("ugnot"), which walks every denomination the address holds. Anyone can send any address a denomination of their own, and nothing caps how many accumulate, so the cost of that read is set by a third party. GetCoin(addr, "ugnot") reads the one.

Render output is now escaped

Render(path) receives whatever a visitor puts in the URL, and several of these realms also echo text that any caller can store. Both flow into markdown that gnoweb turns into a page, so an unescaped value can add structure the realm never wrote. The change routes those values through p/nt/markdown/sanitize/v0, which offers one helper per markdown slot.

One change outside examples/

gnoweb serves a file listing for a realm that declares no Render, and TestRoutes covered that fallback through /r/docs/optional_render, a realm whose entire purpose was to declare none. That realm is folded into hello, so the case now points at /r/demo/disperse, which also has no Render.
