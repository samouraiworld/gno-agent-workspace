**TL;DR:** The gas the VM charges for a native function is fitted from benchmarks, so a benchmark that only ever measures one convenient input size hands the fitter a cost model that ignores the sizes an attacker actually picks. Two natives were mispriced this way: a Merkle hash billed a flat rate no matter how big its two inputs are, and modular exponentiation priced only the modulus while leaving the exponent, which drives the real cost, free. This PR benches both across sizes and off the diagonal, adds a two-argument spec form to the fitter, and hardens the fitter so it warns when any emitted entry undercharges its own worst sampled point.

**Verdict: APPROVE** — both mispricings are real and reproduced with numbers; the PR is a fitter and benchmark change that does not itself move the shipped table, and it now refuses to emit a silent flat charge for a superlinear native (0 Critical, 0 Warning).

## Summary

`gnovm/stdlibs/native_gas.go` is generated by [`gen_native_table.py`](https://github.com/gnolang/gno/blob/3b6861c37/gnovm/cmd/calibrate/gen_native_table.py) from a hand-written spec list. The spec declares each native's cost model, so a wrong spec entry produces a wrong price no matter how good the benchmark is. There is no `go:generate` and no CI job: regeneration is manual, on reference hardware, which is why the committed table does not change in this diff.

Two spec entries were wrong. `crypto/merkle innerHash` was declared `Flat` and benched once at 32 bytes per side, so it billed a constant 7513 for inputs of any length. `crypto/modexp modExp` tied base, exponent and modulus to one size and priced the modulus alone via `SlopeIdx: 2`, leaving the exponent, which drives the modular-squaring loop, unpriced. Both natives accept slices of any length and both are reachable from a realm, so the mispricing is caller-controllable.

The PR adds `NATIVE_SPECS_2ARG` and benches each native across sizes and off the diagonal so the fit can see both axes. It also extends the undercharge replay, previously run only on the two-slope path, to the one-parameter and flat paths, and makes a demotion-to-flat report the measured spread it is flattening.

## Glossary

- native gas table: the generated per-native cost model the VM charges before dispatching a native function; slope terms price per-kilobyte input growth.
- fitter: `gen_native_table.py`, which least-squares-fits each native's benchmarked cost to the cost model its spec declares, then emits a Go table.
- demotion to flat: when a linear or two-arg fit lands below R² 0.5, the fitter replaces it with a constant charge; this is the failure mode that mispriced innerHash.

## Fix

The two spec corrections live in [`NATIVE_SPECS_2ARG`](https://github.com/gnolang/gno/blob/3b6861c37/gnovm/cmd/calibrate/gen_native_table.py#L239): innerHash gains `(0, LenBytes, 1, LenBytes)` so both sides cost per byte, and modExp gains `(1, LenBytes, 2, LenBytes)` so the exponent is priced alongside the modulus. The fitter change is the load-bearing safety part: [`worst_undercharge_1d`](https://github.com/gnolang/gno/blob/3b6861c37/gnovm/cmd/calibrate/gen_native_table.py) replays the emitted integers for single-parameter and flat entries the same way the two-arg path already did, and warns when the worst sampled point is undercharged by more than 2x. A demotion to flat now prints the measured growth across the sampled range, so a genuine flat native reads differently from a superlinear one that fit badly.

## Benchmarks / Numbers

Measured on this branch (AMD Ryzen 7 7840HS), `-benchtime` varying by native:

| Native | small input | large input | ratio | old charge |
|---|---|---|---|---|
| `innerHash` | 1369 ns (L32/R32) | 75742 ns (L4096/R4096) | 55x | flat 7513 |
| `innerHash` asymmetry | 37037 ns (L32/R4096) | 48229 ns (L4096/R32) | — | a single total-bytes axis cannot express this |
| `modExp` | 317486 ns (256B mod, 32B exp) | 9070185 ns (256B mod, 1024B exp) | 28.6x | modulus-only, exponent free |

The fitter's own verdict on the modExp additive model, from a run over fresh benchmark data:

```
WARN: crypto/modexp.modExp additive model fits poorly (R²=-0.267); the emitted
entry undercharges N1=512,N2=512 by 18.1x. Cost is superlinear in these
parameters — the two-slope schema cannot express that.
```

R² below zero means the plane fits worse than a flat charge, and the 18x undercharge is at a benched point, not an extrapolation.

## Verified

- Both mispricings reproduce. `innerHash` measured 1369 ns to 75742 ns across 32 to 4096 bytes per side, a 55x span against the flat 7513 charge; the L32/R4096 vs L4096/R32 asymmetry (37037 vs 48229) confirms two independent axes, which a single total-bytes slope could not capture. `modExp` measured 317486 ns to 9070185 ns at a fixed 256-byte modulus as the exponent grew from 32 to 1024 bytes, a 28.6x span driven entirely by the previously-free argument.
- The change does not move the shipped table. Diffing the emitted `native_gas_table.go.txt` from the pre-change generator against the post-change generator on the same benchmark input produced identical output; the fitter change adds diagnostics only.
- The runtime consumes the second axis. `NativeGasInfo.Slope2` is read in [`chargeNativeGas`](https://github.com/gnolang/gno/blob/3b6861c37/gnovm/pkg/gnolang/native_gas.go#L138) as `cost += gi.Slope2 * nativeSizeFromBlock(...) / 1024`, so the two-arg spec is not inert.
- The re-specced natives are reachable on chain. `crypto/modexp` is wired into `gnovm/stdlibs/generated.go` and callable from any realm; it merged via #5725 but the IBC stdlibs are not deployed yet, which changes urgency, not correctness.
- The extended undercharge check catches a real second case. On a full benchmark run it flagged `crypto/bn254.pairingCheck` demoting to flat while its measured cost moved across the sampled range, the same failure mode that produced innerHash's flat 7513.
- No false positive at proper iteration counts. A `pairingCheck` undercharge that showed at 20 iterations went silent at 300x/count=3, confirming the check is quiet on well-sampled data rather than warning indiscriminately.
- Determinism is unaffected: the fitter is offline tooling, and the emitted table is integer `Base`/`Slope` constants with no float on the runtime charge path.
- Green at 3b6861c37: `go build ./gnovm/...`, `go test ./gnovm/pkg/gnolang/ -run 'TestNativeGas|Gas'`, `go vet ./gnovm/cmd/calibrate/`, and the fitter emits a syntactically valid 60-row table.
